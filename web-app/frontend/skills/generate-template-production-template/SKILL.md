# 模板量产模板生成

## 工作目标

与用户共同设计一个可复用的模板量产模板，并交付通过格式校验的单个 JSON 文件。模板用于定义页面收集哪些内容和素材、怎样生成候选口播文案，以及使用哪种已实现的成片流水线；它不包含某次任务填写的数据、上传文件、生成结果或任务状态。

## 与用户沟通

- 先理解用户希望批量生产什么视频、每次变化什么内容、用户能够提供什么素材，以及成片需要保留的关键特征。
- 只询问会实质改变模板且无法从上下文判断的问题。跳过已经明确的信息；用户让你决定时，基于现有信息继续完成。
- 不预设行业、视觉风格、叙事节奏、文案结构或分析方法。这些由用户需求、参考内容和你的专业判断共同决定。
- 用户提供参考视频时，可使用当前环境中任何合适的能力进行观察、转写、抽帧、拆解或归纳。重点是提炼可复用的输入字段、素材要求、文案规则和生产方式，不要求采用固定的视频分析流程。
- 不把参考视频的路径、内容转写、逐镜数据或用户本次上传的素材写入最终模板，除非它们本身是用户明确要求固化的通用创作规则。

## 创建模板

开始编写前，阅读 [模板格式与运行方式](references/template-format.md)。它说明字段的产品含义、可用占位符和当前支持的成片流水线。

默认选择适合一般量产场景的 `generic_concat_v1`。只能选择服务端实际注册且用户明确需要的流水线，不要发明尚未实现的流水线或响应格式。医疗等敏感行业的模板内容由用户在受控环境中提供，Skill 不内置或推荐任何行业模板。

将最终模板写成一个 UTF-8 编码的 `.json` 文件。模板中的提示词应忠实表达用户确认的创作目标，但本 Skill 不替用户规定具体风格。

## 校验与交付

从本 Skill 目录运行：

```text
python scripts/validate_template.py <模板文件路径>
```

根据脚本报告的字段路径修复模板并重新运行，只有退出码为 `0` 时才把模板作为可导入结果交付。如果连续三次遇到同一个无法通过修改模板解决的错误，停止重试并明确说明阻塞原因，不要声称模板已经通过校验。

校验通过后，可以用包内预览器生成一条本地示例视频：

```text
python scripts/render_preview.py <模板文件路径> --materials <素材目录> --content <示例内容.json> --output <预览视频.mp4>
```

`--materials` 和 `--content` 都是可选的。没有素材时，预览器会为每个素材槽生成占位片段；预览器只在本机调用 FFmpeg，不调用后端、LLM、TTS 或远程服务，并为预览视频加入静音音轨。预览用于确认画幅、素材编排和基本时长，不等同于最终量产成片。

最终回复简要给出：

- JSON 文件路径；
- 选择的 `pipeline_id`；
- 校验通过结果。
- 如生成了预览，附上预览视频路径，并说明它是本地预览。

格式校验只证明模板符合当前系统契约，不代表创意质量、风格选择或参考视频还原程度已经得到用户认可。
